# Languages and accessibility

## Translating

All text the window shows goes through `tr("English text")`, `tr_fmt(...)` or `tr_n(...)`
(`crates/guide-app/src/i18n.rs`); the English text is the message id. A guard test
(`tests/i18n_guard.rs`) fails the build if a user-visible string bypasses translation or if
`locales/template.json` is out of date.

* `locales/template.json` lists every message. Regenerate it with
  `UPDATE_I18N=1 cargo test -p guide-app --test i18n_guard` (inside Docker).
* A translation is `locales/<code>.json`: the same keys with translated values, keeping every
  `{placeholder}`, plus `"_language": "<the language's own name>"` (for example `"Deutsch"`), which the
  language picker shows instead of the code. Plural messages use the forms the language needs. Register it in `CATALOGS`
  in `i18n.rs`; the Appearance section then offers a language choice.
* `SNAPFORGE_LANG=pseudo` shows every message accented and padded - use it to find text that
  is not translated or does not fit. `SNAPFORGE_LANG=<code>` forces a language; otherwise the
  saved setting and then `LC_ALL`/`LC_MESSAGES`/`LANGUAGE`/`LANG` decide.

**Known limits:** no real translation is shipped yet (English only; pseudo is for testing).
Messages from the library crates (capture, export and storage errors, export progress) and the
`--check` output stay in English.

## Appearance

Gear button > Appearance: theme (follow the system, light, dark). Colours come from `src/theme.rs`; its tests check the WCAG
contrast of text (4.5:1) and of the focus ring and borders (3:1) for both themes.

## Keyboard and screen readers

* Every control can be reached with Tab / Shift+Tab; the focused control gets a 2 px high-contrast
  ring (checked by `tests/a11y_e2e.rs`). F1 lists all shortcuts.
* The build includes AccessKit, so screen readers on Linux (AT-SPI, e.g. Orca) get the controls'
  labels. Step rows and the canvases are labelled explicitly; `guide::tests` checks the rows'
  labels and selected state. **Not verified with a real screen reader** - only the exposed
  accessibility tree is tested.
* Drawing annotations on the canvas needs a pointer; there is no keyboard way to draw yet.
